## Depth and statement boundaries

A subprocess runs the compiler and VM on the normal Rust test-thread stack. This isolates a possible stack abort so the parent test reports failure rather than terminating the whole suite. The test does not create a specially enlarged stack. A test-harness-only environment marker selects the worker; it is not a compiler or CLI feature switch.

All four cases lower and execute at the shared maximum depth of 32 source blocks: pure FOR nesting and alternating FOR/IF nesting, each in a contract and in a function with an innermost early return. The return cases place failing assertions after the nested constructs, so successful execution checks that every abandoned continuation is skipped. Equivalent depth-33 sources are rejected with E0205.

Measured Windows VM counters at depth 32:

| Shape | Cost | Peak pairs | Value / environment / operation stack entries |
| --- | ---: | ---: | --- |
| Contract, pure FOR | 935,443 | 60,351 | 808 / 322 / 807 |
| Function return, pure FOR | 919,692 | 67,731 | 817 / 326 / 816 |
| Contract, alternating FOR/IF | 434,970 | 29,837 | 483 / 192 / 482 |
| Function return, alternating FOR/IF | 467,438 | 37,687 | 492 / 196 / 491 |

Each loop executes at most once in these fixtures, keeping the depth check independent of exponential iteration counts. These are specific adversarial shapes, not an exhaustive proof for every program allowed by the source budgets. Counters measure VM entries and allocator statistics, not process RSS or native-stack bytes.

A separate test compiles and executes 256 empty-range loops and rejects 257. It also verifies that a failure after an earlier EMIT aborts with E0500 rather than returning a partial condition list. Existing parser, type, aggregate-value, frame-copy, cost-limit and mixed-depth tests remain.

## Pinned deterministic fixtures

The [golden fixture file](../../crates/compiler/src/clvm/for_next_golden.json) is checked into the source directory so the same assertions run on Windows and native Linux. It contains source text, serialized input environment, independently specified expected heights, program byte length, byte SHA-256, CLVM tree hash, exact execution cost and result bytes.

| Fixture | Program bytes | VM cost | Expected heights |
| --- | ---: | ---: | --- |
| Signed range with mutated bound/step locals | 1,593 | 48,045 | 5, 3, 1 |
| Nested condition order | 3,001 | 92,308 | 99, 11, 21, 22, 100 |
| Nested function return | 3,749 | 44,576 | 21 |
| Dynamic solution bound | 1,559 | 44,792 | 1, 2, 3 |

Every case compiles both LF and CRLF source and requires identical program bytes. Execution must match independently constructed serialized conditions and the pinned result. The exact measured cost must succeed; cost-minus-one must fail with E0501. Program hashes and costs were captured from the reviewed Windows implementation and are now fixed expectations, not values regenerated by the test. Intentional future backend changes require reviewing and explicitly updating these expectations.

These are private unbound CLVM program fixtures, not public CLI manifests or release packages. They do not authorize source loop compilation through public entry points. The user confirmed native Linux testing passed, establishing agreement with the pinned Windows program hashes, costs and result bytes for this fixture set.

## Native Linux verification

From the existing native checkout, copy the manifest and source directory. The latter includes the new golden JSON file:

```bash
set -e
test -f Cargo.toml
rsync -a /mnt/artoo/e/DEV/0xBASIC/crates/compiler/Cargo.toml crates/compiler/Cargo.toml
rsync -a /mnt/artoo/e/DEV/0xBASIC/crates/compiler/src/ crates/compiler/src/
export CARGO_TARGET_DIR="$HOME/.cache/0xbasic/target"
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
```

Expected: 320 Windows / 321 Linux Rust tests, including 43 private FOR/NEXT tests. The depth worker is also invoked by its parent subprocess test. No manual fixture generation, feature flags, simulator rerun or release rebuild is required. A golden mismatch should be investigated rather than automatically replacing its expected values.
